### 1.1 分佣计算精确性验证

#### 1.1.1 基础分佣 — 无分销员场景

| 用例编号 | 实付金额 | 投入成本 | 利润 | 平台比例 | 代理商比例 | 平台佣金 | 代理商佣金 | 验证公式 |
|---------|---------|---------|------|---------|-----------|---------|-----------|---------|
| FC-001 | 100.00 | 60.00 | 40.00 | 50% | 50% | 20.00 | 20.00 | 20+20=40 |
| FC-002 | 200.00 | 100.00 | 100.00 | 30% | 70% | 30.00 | 70.00 | 30+70=100 |
| FC-003 | 50.00 | 50.00 | 0.00 | 50% | 50% | 0.00 | 0.00 | 利润为0 |
| FC-004 | 99.99 | 60.00 | 39.99 | 50% | 50% | 20.00 | 20.00 | 四舍五入:19.995->20.00 |
| FC-005 | 0.01 | 0.00 | 0.01 | 50% | 50% | 0.01 | 0.00 | 0.005->0.01(平台),0.005->0.00(代理商)? |
| FC-006 | 100.00 | 0.00 | 100.00 | 8% | 92% | 8.00 | 92.00 | 参照今夜到家比例 |
| FC-007 | 37.50 | 20.00 | 17.50 | 40% | 60% | 7.00 | 10.50 | 7+10.5=17.5 |

**重点验证**：
- FC-004：四舍五入后平台+代理商是否仍等于利润？若19.995四舍五入为20.00，两个20.00=40.00>39.99，差0.01元归谁？
- FC-005：极小金额下精度分配规则，两方各0.005如何取舍？是否存在"先分后分"优先级？

**测试步骤**：
```
1. 后台设置平台比例X%、代理商比例Y%，确保X+Y=100
2. 创建对应业务订单，设置商品原价（投入成本）
3. 用户完成支付
4. 查看后台分佣明细：
   a. 利润 = 实付 - 投入成本
   b. 平台佣金 = 利润 x 平台比例（精确到分）
   c. 代理商佣金 = 利润 x 代理商比例（精确到分）
   d. 平台佣金 + 代理商佣金 = 利润（不多不少）
5. 若四舍五入导致总和不等于利润，确认尾差处理规则
```

### 1.3 退款对分佣影响 — 全场景覆盖

#### 1.3.1 全额退款

```
前置条件：
- 订单实付100元，成本60元，利润40元
- 平台50%(20元)，代理商50%(20元)
- 佣金状态：待结算

操作：全额退款100元

预期：
- 平台佣金明细新增冲抵记录：-20.00元
- 代理商佣金明细新增冲抵记录：-20.00元
- 待结算余额相应减少
- 订单状态变为REFUNDED
```

#### 1.3.2 部分退款

```
前置条件：同上

操作：部分退款40元

预期：
- 新的实付 = 100 - 40 = 60元
- 新的利润 = 60 - 60 = 0元（利润变为0！）
- 平台佣金差额 = 0 - 20 = -20元（冲抵记录）
- 代理商佣金差额 = 0 - 20 = -20元（冲抵记录）
- 或者：利润 = (100-40) - 60*(60/100) = 60 - 36 = 24？（成本是否按比例退？需确认）

关键问题：部分退款时，成本如何重算？
- 方案A：成本不变，新利润 = 新实付 - 原成本
- 方案B：成本按比例退，新利润 = 新实付 - 新成本
- 这两种方案导致的分佣结果完全不同！需与开发确认
```

#### 1.3.3 佣金已提现后退款（最复杂场景）

```
时间线：
T1: 订单完成，利润40元，代理商佣金20元进入"待结算"
T2: 结算周期到达，代理商佣金20元变为"可提现"
T3: 代理商申请提现20元，运营审核通过，打款成功
T4: 用户申请全额退款

预期：
- 代理商余额不足扣回 -> 产生欠款记录20元
- 下一笔佣金到账时自动扣除欠款
- 若下笔佣金15元 -> 扣除15元抵欠款 -> 剩余欠款5元 -> 代理商实得0元
- 直到欠款清零

测试步骤：
1. 完成一笔订单，确保分佣生成
2. 手动推进结算周期（或修改测试环境时间）
3. 代理商提现全部佣金
4. 对该订单执行退款
5. 验证欠款记录生成
6. 再完成一笔新订单
7. 验证新佣金是否自动扣除欠款
8. 验证扣款金额和剩余欠款的准确性
```

#### 1.3.4 多级分销退款连锁冲抵

```
前置条件：
- 利润40元，平台20元，代理商14元，一级4元，二级2元
- 全部处于"待结算"状态

操作：全额退款

预期（需逐一验证）：
- 平台冲抵：-20.00元
- 代理商冲抵：-14.00元
- 一级分销员冲抵：-4.00元
- 二级分销员冲抵：-2.00元
- 合计冲抵：-(20+14+4+2) = -40.00元 = -利润

混合场景：
- 平台佣金待结算、代理商已提现、一级待结算、二级已提现
- 验证各方冲抵/欠款机制是否正确独立运作
```

#### 1.3.5 部分退款后再次部分退款

```
前置条件：实付100元，成本60元，利润40元

第一次部分退款30元：
- 新实付70元，新利润需重算（依据确认的方案）
- 各角色佣金调整

第二次部分退款20元：
- 新实付50元，再次重算
- 各角色佣金再次调整
- 累计退款50元，累计冲抵正确

第三次尝试退款60元（超出剩余可退50元）：
- 应被拦截
```

## 八、三端数据一致性深度测试方案

### 8.1 核心操作后三端验证

对每个核心操作，验证用户端、商家端、后台三端数据完全一致。

#### 8.1.1 餐饮扫码支付后

```
操作：商家生成码->用户扫码支付80元

用户端验证：
- 我的订单 -> 出现该订单
- 订单状态：已支付/已完成
- 金额：原价100/优惠20/实付80

商家端验证：
- 订单管理 -> 出现该订单
- 状态、金额与用户端一致
- 今日流水增加80元
- 核销笔数+1

后台验证：
- 订单列表 -> 出现该订单
- 订单类型标识为"餐饮扫码"
- 分佣明细已生成
- 金额与用户端/商家端一致
```

#### 8.1.2 退款后

```
操作：对上述订单执行全额退款

用户端验证：
- 订单状态变为"已退款"
- 退款金额显示正确
- 收到退款通知（订阅消息/短信）

商家端验证：
- 订单状态变为"已退款"
- 今日流水是否扣减80元
- 退款按钮消失/置灰

后台验证：
- 订单状态REFUNDED
- 分佣明细新增冲抵记录
- 佣金余额相应减少
- 对账报表数据更新
```

#### 8.1.3 人工辅助核销后

```
操作：用户提交凭证->运营审核通过->下发验证码->商家核销

用户端验证：
- 订单状态经历：待审核->验证码已下发->已完成
- 可查看验证码
- 收到推送通知

商家端验证：
- 核销记录出现
- 订单状态"已完成"

后台验证：
- 订单全流程状态记录完整
- 审核记录（谁审核的/什么时间/通过/驳回理由）
- 分佣正确生成
```
