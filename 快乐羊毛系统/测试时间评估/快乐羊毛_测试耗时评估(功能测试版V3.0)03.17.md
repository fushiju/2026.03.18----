# "快乐羊毛"测试耗时评估（功能测试人员版 V3.0）

> **评估日期**：2026-03-17
> **基础版本**：V1.0（2026-03-14，基于369条用例）
> **本版更新**：基于V3.0完善版需求文档和452条用例重新评估
> **测试人员**：1人，功能测试工程师
> **评估场景**：开发提测后，跑通第一个完整流程版本
> **用例总数**：452条（P1:200 / P2:164 / P3:78 / P4:10）
> **相比V1.0**：新增83条用例（3个全新模块+12个模块补充），新增约1.5个工作日

---

## 一、评估调整说明（与高级测试的差异）

| 维度 | 高级测试工程师 | 功能测试工程师（本人） | 影响 |
|------|--------------|---------------------|------|
| 需求理解 | 快速抓重点 | 需要反复对照需求文档 | 每个模块多花10-15min理解 |
| 用例执行速度 | 熟练，平均8min/条 | 需要对照用例步骤执行，平均12min/条 | **整体耗时×1.5倍** |
| 分佣计算验证 | 心算+表格快速核对 | 需要用计算器逐步算，容易算错要反复确认 | 分佣模块**耗时×2倍** |
| 安全性测试 | 会用抓包工具 | 不太会用Fiddler/Charles抓包 | 安全测试可能**跳过或简化** |
| 并发/性能测试 | 能用工具模拟 | 只能手工模拟双人操作 | 并发测试**简化执行** |
| Bug记录 | 快速截图+描述 | 需要想清楚怎么写才清楚 | 每个Bug多花3-5min |
| 环境问题 | 自己排查 | 可能需要找开发帮忙 | 额外等待时间 |
| 多端操作 | 流畅切换 | 商家端/用户端/后台来回切换容易乱 | 多端模块多花20% |
| 新系统熟悉度 | — | 快乐羊毛还在学习阶段 | 前2天会偏慢 |

**总体系数：功能测试人员耗时 ≈ 高级测试 × 1.5~1.8倍**

## 二、第一轮：冒烟测试 — 详细耗时

> 目标：确认每个模块核心主流程能跑通，不通过则打回
> 冒烟用例数：58条（从452条中精选核心主流程）

| 序号 | 模块 | 冒烟场景 | 耗时 | 备注 |
|------|------|---------|------|------|
| 1 | **环境准备** | 后台登录、小程序体验版安装、微信账号准备、熟悉后台菜单布局 | 60min | 首次上手要找各个入口在哪 |
| 2 | **免费资料区** | 进列表→点详情→复制链接 | 15min | 简单，能快速过 |
| 3 | **外卖红包** | 看5个Icon→点美团→看跳没跳转→渠道优选确认 | 20min | 需要在手机上操作，切App确认 |
| 4 | **外卖通用券** | 选面额→付钱→看卡密出没出来 | 30min | 第一次真实支付会谨慎，要反复确认金额 |
| 5 | **餐饮-品牌直跳** | 看品牌列表→点麦当劳→看跳转 | 15min | |
| 6 | **餐饮-系统直连** | 登商家端→输金额→生成二维码→换手机扫码→付钱→退款 | 45min | **要操作两端**，第一次搞清楚流程比较花时间 |
| 7 | **餐饮-人工辅助** | 后台录商家→审核→用户下单→传照片→运营审核→输验证码→核销 | **70min** | **最复杂**，要来回切3个端（后台/用户/商家），每步都要找按钮在哪 |
| 8 | **打车服务** | 点打车→授权定位→看跳转 | 10min | |
| 9 | **电影票务** | 看片单→选座→付钱→看出没出票 | 30min | 选座操作要摸索一下 |
| 10 | **会员充值** | 选话费→输号码→付钱→等到账 | 25min | 要等充值到账，可能要等几分钟 |
| 11 | **家电购物** | 看商品→点购买→看跳没跳京东 | 10min | |
| 12 | **购物返利** | 授权→贴链接→看转链结果 | 20min | 第一次授权流程要摸索 |
| 13 | **个人中心** | 微信登录→看订单→看佣金→提现 | 20min | |
| 14 | **加油/充电** | 点入口→授权定位→看列表→点跳转 | 10min | V3.0新增模块，CPS跳转，简单 |
| 15 | **商家端** | 登录→试收银台→看订单→品牌账号管理 | 30min | 要搞清楚主账号和子账号的区别 |
| 16 | **选品仓库** | 点一键同步→看列表→试上架→type_id筛选 | 30min | 后台操作，要找到入口 |
| 17 | **分佣系统** | 配比例→确认平台+代理商=100%→跑一笔单→拿计算器算对不对 | 45min | **要手动算分佣**，容易出错要反复核对 |
| 18 | **订单状态机** | 看之前跑的订单状态对不对 | 15min | 结合已跑的订单验证 |
| 19 | **消息通知** | 翻手机看有没有收到推送 | 10min | |
| 20 | **安全性** | 基础越权验证+支付金额篡改 | 15min | 简化执行 |
| 21 | **整理冒烟结果** | 记录哪些通了哪些没通，写个简单报告 | 20min | |

## 九、给自己的实操建议

| 建议 | 说明 |
|------|------|
| **先做简单模块找感觉** | Day4先测免费资料区和外卖红包，操作简单，建立信心 |
| **分佣计算用速查表** | 打开"快乐羊毛_分佣速查表(V3.0完整版v2).xlsx"，填数字自动算，不用手动计算 |
| **记住分佣核心：平台+代理商=100%** | 分销员从代理商里扣，利润全分完没有剩余 |
| **餐饮人工辅助分两天测** | 这个模块一口气测完会很混乱，分两天每天8-9条 |
| **每测完一个模块就记Bug** | 不要攒到最后一起记，容易忘细节 |
| **截图要带时间戳** | Bug截图时带上时间，方便开发定位日志 |
| **不会的场景先跳过** | 安全测试（抓包/XSS）如果不会，标记"待协助"先跳过 |
| **多问开发** | 第一次测新系统，流程不确定的地方直接问，别自己猜 |
| **V3.0新增的分佣用例重点关注** | 12条分佣补充用例是核心，特别是fybc-001(100%验证)和fybc-004(原价影响) |
